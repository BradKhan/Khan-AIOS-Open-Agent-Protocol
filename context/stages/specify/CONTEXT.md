# Specification stage

## Inputs
- Research artifact, GitHub issue, current behavior, and approved project constraints.
- Canonical references declared for `specify`.

## Process
- Define testable behavior, non-goals, dependencies, and risk tier.
- For substantial work, use Spec Kit's specification and planning path.
- Preserve a single accepted spec; do not repeat Superpowers planning.
- Explicitly identify unresolved decisions that require an authorized owner.

## Outputs
- Accepted issue/spec with criteria, implementation plan, and verification approach.
- Hand off a stable, linked task to `implement`.

## Permissions
- Propose requirements and architecture; only authorized review accepts changes.
- No implementation permissions are implied by this stage.

## References
- Use `context/routes.json` for the relevant canonical files.
