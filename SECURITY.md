# Security policy

Use GitHub private vulnerability reporting where available. Do not publish live credentials or personal data in issues.

Trust boundaries include PR code, external skills, fetched research, model-generated shell commands, credentials, GitHub webhooks and long-running agent workspaces. Review executable skills before installation and pin source revisions.

Requirements: least-privileged tokens, immutable GitHub Actions references, isolation for untrusted code, webhook authentication, auditability, redaction, and human approval for production or critical changes. A green template check is not a security certification.
