# Feature specifications

The core requires only testable GitHub issue acceptance criteria. For standard/critical work, use GitHub Spec Kit to create a fuller spec, plan, task breakdown and convergence check when that improves execution.

Specs are canonical behavior descriptions, not issue copies. Record changed behavior in a reviewed diff linked to its issue and PR. OpenSpec-style deltas are useful as a concept for brownfield projects but a second mandatory spec system is not.

Do not rerun Superpowers brainstorming and writing-plans as mandatory duplicate phases after a Spec Kit plan is accepted. Debugging/TDD/worktrees remain appropriate.
